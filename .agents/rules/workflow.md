# 開発の進め方（作業ルール）

AI エージェントがこのプロジェクトで開発するときの手順です。`AGENTS.md` から参照されます。

## 用語
- **段階**：開発の 1 ステップ。1 段階 ＝ 1 ブランチ ＝ 1 PR
- 段階の一覧と順番は、このファイルの末尾「段階の一覧」に従う

## 確認
- ユーザーの確認が必要な場面（方針が複数ある、費用や外部公開が関わる、元に戻しにくい操作、API キーなど秘密の値が要る）では、**実行する前に確認をとる**
- 確認なしで次の段階に進まない

## 出力
- 返答、ドキュメント、コメント、コミットメッセージ、PR の本文は日本語で書く

## Python
- Python を使う場合は、必ず仮想環境（`python3 -m venv .venv`）を作って、その中で実行する
- `.venv/` は Git に入れない

## Git と GitHub
- リポジトリ：GitHub の `Google_AI_Challenge_2026`（Public）
- git / gh / node は WSL（Ubuntu）側のものを使う
- 段階ごとに `main` からブランチを切る。ブランチ名は `stage-NN-内容`（例：`stage-01-nextjs-setup`）
- **ブランチは merge 後も削除せずに残す**（`gh pr merge` の `--delete-branch` は使わない）
- 段階の作業が終わったら、そのブランチを push して PR を作る
- **ユーザーが PR を merge したことを確認してから**、`main` を pull して次の段階に取り掛かる
- 公開リポジトリなので、秘密の値（`.env.local` など）や実在の人の日記を絶対にコミットしない

## 1 つの段階の流れ
1. `main` を最新にする（`git pull`）
2. `next-plans/NN_段階名.md` に、これから何をする予定かを書く（目的、作業内容、変更するファイル、確認してほしいこと）
3. 必要ならユーザーに確認をとる
4. ブランチを切って実装する
5. 動作確認をする（ビルド、lint、スマホ幅 375px での表示など）
6. `logs/NN_段階名.md` に、何を実装したか、それによって何が変わったかを書く
7. コミットして push し、PR を作る（PR の本文には next-plans と logs の要点を書く）
8. ユーザーの merge を待つ

## ファイルの書き方
### next-plans/NN_段階名.md
- 目的
- やること（箇条書き）
- 作る・変えるファイル
- ユーザーに確認したいこと、必要なもの（API キーなど）

### logs/NN_段階名.md
- 実装したこと
- それによって変わったこと（できるようになったこと）
- 動作確認の結果
- 残った課題、次の段階への引き継ぎ
