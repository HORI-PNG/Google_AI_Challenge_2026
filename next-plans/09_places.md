# 段階9：今日の過ごし方の提案（近くの実際の場所）（予定）

## 目的
段階8 の予報で出る「おすすめの場所」（図書館・カフェ・公園など）を、**今いる場所の近くにある実際の場所**にする。
「今日は、どこで・何を・いつすればいいか」の「どこで」を、そのまま行ける形にする。

## やること
- 予報カードのおすすめの場所に「近くの〇〇を探す」ボタンを付ける（図書館・カフェ・公園。家・学校は探さない）
- ボタンを押したときだけ、ブラウザの位置情報を使う
  - 位置情報は初期設定でオフ（privacy.md）。初めて押したときに「位置情報を使って近くの〇〇を探しますか？」と聞き、OK なら設定をオンにする
  - 設定画面に「近くの場所を探す（位置情報）」のオン・オフを付ける（`settings.locationEnabled` は段階2 から用意済み）
- `POST /api/places`（ログインした人だけ）：サーバー側で Places API（New）の Nearby Search を呼ぶ
  - 入力：場所の種類と緯度・経度（小数第 3 位＝約 100m に丸めてから送る）
  - 出力：近い順に 3 件まで。名前・距離・営業中かどうか・Google マップで開くリンク
  - 取る項目を最小限にして（フィールドマスク）、費用を抑える
  - **位置情報は保存しない・ログに出さない**
- 同じ日・同じ種類・ほぼ同じ場所なら、ブラウザに結果を覚えておき、Places API を何度も呼ばない
- API キーがない・位置情報を断られた・見つからないときは、「Google マップで『図書館』を検索する」リンクを出す（API を使わず、費用もかからない）
- デモ用：位置情報を断った人でも流れが分かるようにする
- テスト（入力の確かめ、距離の計算、丸め、結果の整形）、PLAN.md・`.env.example` の更新

## 作る・変えるファイル
- 新規：`src/lib/places.ts`（種類・丸め・距離・zod）、`src/app/api/places/route.ts`、`src/components/home/NearbyPlaces.tsx`、`tests/unit/places.test.mjs`
- 変更：`src/components/home/HomeParts.tsx`（予報カードのおすすめの場所）、`src/components/SettingsScreen.tsx`、`src/lib/userProfile.ts`・`AuthProvider.tsx`（位置情報の設定の保存）、`.env.example`、PLAN.md

## 決めたこと（ユーザーに確認済み）
- **費用が怖いので、一旦は無料でできる範囲で進める**。請求先は登録せず、Places API は使わない
  - 初期（`NEXT_PUBLIC_PLACES_API_ENABLED` が true でない）：おすすめ場所ごとに「近くの〇〇を Google マップで探す」リンクだけを出す。位置情報も使わない
  - Places API を使う作り（`/api/places`、営業中の表示つき）は用意しておき、あとで決めたら `.env.local` だけで切り替えられる

## ユーザーに確認したいこと・必要なもの
- **Google Maps Platform の API キー**（`GOOGLE_MAPS_API_KEY` を `.env.local` に入れる）
  - Google Cloud で、Firebase と同じプロジェクトに「Places API (New)」を有効にし、API キーを作る
  - 請求先アカウント（クレジットカード）の登録が必要。月ごとの無料枠の範囲で使う想定（個人の開発・デモなら無料枠に収まる見込み）
  - キーの制限：「API の制限」で Places API (New) だけに絞る。割り当て（1 日のリクエスト上限）を小さく設定しておくと、使いすぎを防げる
- 営業中かどうかを出すか（出すと、1 回あたりの料金区分が上がり、無料枠が小さくなる）
